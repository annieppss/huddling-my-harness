# R4 — 산출물과 재개

구현 기본값. 실행 규칙의 SSOT는 `harness/rules.json` 한 개다. `design.md`는 원문 근거,
`harness/schemas/*.json`은 필드 형식 계약이며 토큰 값이나 서비스 정책을 중복 정의하지 않는다.
원문 변경은 자동 덮어쓰지 않고 규칙 파일에 검토·반영한다.

각 실행은 `runs/<run-id>/`에 저장한다.

| 단계 | 파일 | 책임 |
|---|---|---|
| 입력 | brief.json | 본인이 정한 화면 ID와 실제 레퍼런스 발췌 |
| 기준 스냅샷 | context/ | 시작 시 PRD·디자인·스토리·규칙·계약·역할 문서 고정 |
| 분석 | research/artifact.json | 근거와 서비스 반영 요소 |
| 설계 | plan/artifact.json | 화면·역할·서비스 스토리 연결·흐름·자산 정책 |
| 키스크린 | concept/artifact.json | 2~3개 390×844 프레임 명세 |
| 확장 | design/artifact.json | 토큰·컴포넌트·전체 요청 화면 명세 |
| 판정 | review/artifact.json | 독립적인 읽기 전용 검토 결과 |
| 실행 기록 | state.json | 입력·출력 해시, 완료 단계, 컨셉 승인 기록 |
| 실패 기록 | reports/*-rejected.json | 최근 거절된 응답과 실패 원인 |

매 단계는 원자적으로 저장한다. `.lock`으로 동시 쓰기를 차단한다.
`status`는 저장된 성공 문자열을 신뢰하지 않고 파일 해시와 검사를 다시 확인한다.
앞 단계·brief·스냅샷이 바뀌면 해당 단계부터 영수증을 무효화하고 재실행을 요구한다.
컨셉 또는 그 이전 입력이 바뀌면 승인이 무효화된다. 디자인 수정만으로 컨셉 승인이 취소되지는 않는다.
판정 코드 변경도 영수증을 무효화한다. 시작 후 원본 PRD가 변경되어도 실행은 고정된 스냅샷을 사용하므로 새 기준은 새 run으로 시작한다.
`rewind`는 이전 파일을 지우지 않고 해당 단계 이후 완료 기록을 취소한다.

장애 후 `.lock`이 남았다면 기록된 PID가 종료됐는지 사람이 먼저 확인한다. 살아 있는 실행의 잠금은 제거하지 않는다.
