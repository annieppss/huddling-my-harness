# R5 — 게이트

구현 기본값. 실제 과거 경험에서 필수였다고 주장하지 않는다.

| 검사 | 통과 조건 | 실패 시 |
|---|---|---|
| 입력·산출물 계약 | 필수 필드 누락 0, 타입 오류 0, 미해결 자리표시자 0, 중복 ID 0 | 현재 단계 수정 |
| 레퍼런스 근거 | evidence가 해당 입력 excerpt에 실제 포함됨 | research 복귀 |
| 화면 범위 | 요청 screen_ids와 설계·최종 화면 ID 집합 동일, 흐름 누락 0 | plan 복귀 |
| 키스크린 | 고유 화면 2~3개, 너비 390·높이 844 | concept 수정 |
| 사람 승인 | 현재 컨셉·선행 입력 해시에 일치하는 운영진 승인 기록 1건 | 대기 |
| 토큰 | 규칙 파일과 값·이름이 정확히 일치, 미등록 참조 0 | design 복귀 |
| 형태·색 | 인터랙션 pill, 입력 16px, 그림자 0, 파란 CTA 0, 화면당 파랑 최대 2개 | design 복귀 |
| 서비스 불변 조건 | 기본 공개 범위 private, 소유자 선택 필수, 판매 검수 필수, 판매 신청 역할 seller/admin | plan 또는 design 복귀 |
| 독립 검토 | 필수 3개 검사 모두 pass, fail·unknown·findings 0건 | 판정의 return_to 단계로 복귀 |

**서비스 기준을 위반하면 걸리는 검사**는 asset_policy의 기본 비공개·소유자 선택·판매 검수다.
이것은 디자인 명세의 선언을 검사하며, 실제 앱의 접근 권한을 증명하지 않는다.
자연어 화면 설명의 정책 충돌은 독립 검토자가 검사한다. 개인정보·기밀·저작권은 숫자 플래그만으로 보장할 수 없으므로
의심·불명확한 경우 unknown으로 막고 사람이 사실을 확인한다. AI 검토는 법적 권리 확인을 대신하지 않는다.

## 사람 승인 한 곳

concept 통과 후 design 전에 운영진이 터미널에서 `approve --reviewer 이름`을 실행하고 표시된 해시를 직접 입력한다.
파이프 입력과 자동 승인 옵션은 지원하지 않는다. 에이전트는 이 명령을 실행하지 않는다.
이름·시각·해시 기록이며 인증 서버나 전자서명은 아니다. 로컬 파일을 직접 고칠 권한을 가진 사람에 대한 위조 방지는 보장하지 않는다.
실제 Figma 컨셉 검토가 필요하면 운영진은 명세와 외부 시안을 대조한 후 승인한다. 하네스는 시안 파일을 자동 확인하지 않는다.

## 디자인 원문 충돌 해결 기본값

- 전체 Do's and Don'ts를 우선해 세그먼트·모달·토스트 포함 그림자를 모두 금지한다.
- 추천 요금제는 밝은 회색 canvas-soft를 사용한다. 예시의 polarity inversion은 사용하지 않는다.
- 구체적인 입력 컴포넌트 규칙을 일반 pill 문구보다 우선해 input은 rounded.sm을 사용한다.
- on-primary 값은 원문의 흰색 라벨 설명에서 #ffffff로 정규화했다.
- design.md 원문은 수정하지 않는다. 실행되는 선택은 rules.json에 명시했다.

크기·토큰 검사는 JSON에 기재된 수치만 검사한다. 실제 Figma 노드와 픽셀, 터치 영역, 360px 반응형 동작은 아직 검사하지 않는다.
완료 상태를 `structured_design_passed`로 명명하여 앱·시안 구현 완료와 구분한다.
