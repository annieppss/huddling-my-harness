# Codex 카드뉴스 제작 순서

1. README.md와 settings의 두 설정을 읽는다. 자신의 Figma 파일·전용 페이지와 사용할 권한이 있는 캐릭터 자산을 준비한다. init으로 새 실행을 만들고 재개 시에는 state.json을 먼저 읽는다.
2. 공식 자료를 찾아 실제 본문을 읽고 sources.json에 주장·근거·확인 구간을 기록한다. 가상 예시와 실제 기능을 구분한다.
3. 6장으로 구성한다. 표지는 주제, 본문4장은 주제에 맞는 장면·비교·과정, 마지막은 저장용 요약이다. 본문은 그림으로 보여줄 의미를 먼저 정하고 visual_explanation을 작성한다. 캐릭터는 의미 있는 행동·표정으로 설명하고 도식 중심 장에서 생략하면 이유를 남긴다.
4. 풀이1~2줄, 짧은 말풍선·라벨을 쓴다. 긴 문단을 여러 상자로 나누지 않는다. 주제에 맞는 캐릭터 자산과 렌더러를 준비하고 render-script를 실행한다. 현재 렌더러는 설문→알림 예시이므로 다른 주제의 문구만 바꿔 같은 결과를 재사용하지 않는다.
5. Figma 도구의 사용 지침을 읽고 지정한 전용 페이지에 편집 가능한 텍스트·도형·화살표와 별도 그림을 배치한다. 이전 결과와 겹치지 않게 한다. 실제 생성 노드ID·이미지 해시를 기록한다. 불명확한 쓰기는 재시도 전에 실제 상태를 확인한다.
6. 1080×1350 PNG6장을 내보내고 preview.py로 미리보기와375/432px 보기를 만든다. 전 장 원본·축소본을 직접 확인한다.
7. QA-01~06 및 본문02~05 visual_checks에 근거를 남긴다. 텍스트 상자 위주나 의미 없는 캐릭터 배치는 fail이다. 이미지 확인 없이 pass로 쓰지 않는다. 최신 문구·출처·Figma·PNG 해시를 계산한다.
8. check로 계약을 확인한다. 필수 문제는 revise로 새 버전에 수정하되 최대2회. 권고만 남으면 반복 수정하지 않는다. 재개해도 수정·재시도 예산을 초기화하지 않는다.
9. PNG·편집 원본·출처·검수 기록과 남은 한계를 사용자에게 전달한다. 사람 판단은 pending으로 유지한다. 실제 게시·공유는 사용자의 요청 범위에 따른다.
